============================================================
                 BANK-LEDGER API DOCUMENTATION
============================================================

Base URL:
http://localhost:3000/api


============================================================
AUTH APIs
============================================================


1. USER REGISTER
------------------------------------------------------------

WHO CAN ACCESS:
Public

METHOD:
POST

URL:
http://localhost:3000/api/auth/register

EXPECTED SUCCESS:
Status: 201 Created

Description:
New normal user is registered successfully.

EXPECTED ERRORS:
400 → Invalid or missing user information
409 → Email already exists
500 → Server error


2. USER LOGIN
------------------------------------------------------------

WHO CAN ACCESS:
Public

METHOD:
POST

URL:
http://localhost:3000/api/auth/login

EXPECTED SUCCESS:
Status: 200 OK

Description:
Normal user is authenticated successfully.

EXPECTED ERRORS:
400 → Invalid or missing input
401 → Invalid email or password
500 → Server error

============================================================
TRANSACTION APIs
============================================================


11. USER → USER TRANSACTION
------------------------------------------------------------

WHO CAN ACCESS:
Authenticated User

METHOD:
POST

URL:
http://localhost:3000/api/transactions

EXPECTED SUCCESS:
Status: 201 Created

Description:
Transfers money from the authenticated user's account to
another active user's account.

EXPECTED ERRORS:
400 → Invalid input or amount
401 → Unauthorized
404 → Receiver account not found
409 → Duplicate or conflicting idempotency key
500 → Transaction failed


12. GET MY TRANSACTIONS

URL:
http://localhost:3000/api/transactions

EXPECTED SUCCESS:

EXPECTED ERRORS:
401 → Unauthorized
500 → Server error


13. GET MY TRANSACTION BY ID
------------------------------------------------------------

WHO CAN ACCESS:
Authenticated User

METHOD:
GET

URL:
http://localhost:3000/api/transactions/:transactionId

EXPECTED SUCCESS:
Status: 200 OK

Description:
Returns details of a specific transaction accessible to the
authenticated user.

Example:
http://localhost:3000/api/transactions/TRANSACTION_ID

EXPECTED ERRORS:
400 → Invalid transaction ID
401 → Unauthorized
404 → Transaction not found
500 → Server error


14. REQUEST DEMO FUNDS
------------------------------------------------------------

WHO CAN ACCESS:
Authenticated User

METHOD:
GET

URL:
http://localhost:3000/api/transactions/demo-funds

EXPECTED SUCCESS:
Status: 201 Created

Description:
Requests demo funds for the authenticated user's account.

Rule:
Maximum ₹500 per user account per day.

EXPECTED ERRORS:
400 → Funding request is invalid or daily limit reached
401 → Unauthorized
404 → Account not found
500 → Server error

============================================================
COMMON STATUS CODES
============================================================

200 → Success
201 → Created successfully
400 → Bad request / invalid input
401 → Unauthorized
403 → Forbidden
404 → Resource not found
409 → Conflict / duplicate request
500 → Internal server error
